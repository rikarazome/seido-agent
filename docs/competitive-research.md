# 類似サービス・先行事例 徹底調査（2026-06-10実施）

4並列エージェントによる調査結果の統合。角度: ①国内民間 ②政府・自治体公式 ③OSS・学術 ④海外＋ハッカソン既出。

## 結論: Go（ただしポジショニング修正が必要）

**「一般市民向け × ヒアリング→該当判定→条文根拠の一気通貫 × LLM自動形式化」をやっているものは存在しない。**
ただし最大競合のOpenFisca-Japanと、優勝済み類似テーマのフクシアに対する明確な差別化ストーリーが必須。

## 脅威マップ

### 🔴 最重要: OpenFisca-Japan + 支援みつもりヤドカリくん
- Project Inclusive / 貧困予防研究所（Code for Japan系）。活発に開発中（2026-04にv2.1.2）
- 約30制度を**人手でPythonコーディング**。世帯情報→給付シミュレーション
- **Cloud Runにデプロイ済み**（インフラ構成まで被る）
- `/trace`エンドポイントで計算過程の依存木を出せる（≠条文根拠）
- **やっていないこと**: LLMによる条文の自動形式化、対話ヒアリング、条文ベースの証明提示、質問生成

### 🟡 要注意: フクシア（Google Cloud AI Agent Hackathon 2025 最優秀賞）
- 社会福祉士向け業務支援エージェント（アセスメント作成＋支援制度提案）
- 同系統テーマが既に頂点を取っている = 審査ウケは実証済み / 二番煎じに見えるリスク
- **違い**: 専門職向け業務効率化 vs 本プロジェクトは市民向け該当判定＋形式的根拠

### 🟢 終了・非競合
- **Civichat**: 最も近い思想（ヒアリング→判定）だったが2022年9月終了。根拠提示はなかった
- **マイナポータルぴったりサービス**: 検索・申請のみ。該当判定なし
- **デジタル庁 給付支援サービス**: 自治体向けバックオフィス。住民向け判定ではない
- **Zaim わたしの給付金**: プロフィールから自動抽出のみ。根拠なし。プレミアム限定
- **事業者向け補助金マッチング**（SAMURAI等多数）: 領域が違う（B2B）。根拠提示なし
- **自治体AIチャットボット**: 窓口案内どまり

### 海外
- **mRelief**(米): ChatGPT活用、SNAP特化、2分判定。21億ドルの給付アンロック実績 → 課題の規模の証拠に使える
- **Propel**(米): Claude採用、citation提示 → ただしLLM+RAGどまり。**形式的証明はどこもやっていない**
- **entitledto/Turn2us**(英): ルールエンジン（人手構築）による判定。条文根拠なし

### 学術（技術的新規性の境界）
- **PROLEG+LLM**（arxiv 2601.01477, 2026-01）: LLMで法文→PROLEGルール変換をGDPRで実証。**日本の社会保障への適用は未実施**
- **税法×Prolog**（arxiv 2508.21051, 2025）: LLM形式化+Prolog推論で監査可能な税計算。米国税法
- **L4L**（SMT）、**XAI-LAW**（ASP）等: 法×記号推論は活発な研究領域
- → 「LLM自動形式化+記号推論」自体の学術的新規性はないが、**日本の制度への適用＋プロダクト化は未踏**

## 差別化ポジション（審査で語る順番）

1. **OpenFisca-Japanとの差**: 彼らのボトルネックは「制度1つずつ人手でPythonを書く」こと。本プロジェクトは**LLM形式化エージェントで制度追加を自動化**する。30制度/数年 → N制度/日。これがまさに「つくる・まわす・とどける」
2. **根拠の質**: 計算トレース（OpenFisca）でも citation（Propel）でもなく、**条文に紐づく証明木**。「貰える」と言う以上、理由を監査可能にする
3. **対話の必然性**: Prologの未束縛変数から「何を聞けば判定が確定するか」を機械的に導出 → エージェントの質問に根拠がある
4. **市民向け**: フクシアは専門職向け。申請主義の取りこぼしは市民自身の課題

### 想定問答
- 「OpenFisca-Japanと何が違う？」→ ルール作成の自動化と条文証明木。むしろ彼らの課題（スケールしない人手コーディング）を解く進化形
- 「フクシアと被ってない？」→ ユーザーも出力も違う。あちらは業務支援、こちらは判定＋証明
- 「LLMの形式化を信用できるの？」→ 検証エージェント+テストケース+人間レビュー。検証コストを推論時から構築時に移すのが設計思想

- デジタル庁が法令ハッカソンを開催中 = Rules as Codeは政策的追い風。提出資料で言及する価値あり
