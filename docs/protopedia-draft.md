## 作品名

制度エージェント — あなたが貰い損ねているお金を、根拠付きで見つける

## 概要（短文・一覧に表示される紹介文）

日本の社会保障は申請主義。知らない制度は1円も貰えません。制度エージェントは、チャットで家族構成を話すだけで、東京23区×220制度から「受給見込みのある制度」を金額・該当理由・条文リンク・推論ツリー付きで提示します。判定にLLMは一切関与せず、SWI-Prologの論理推論のみで行うため、ハルシネーションが構造的に起こりません（Gemini は対話の理解と応答だけを担当）。

## ストーリー・説明文（本文）

### 課題

日本の社会保障・補助金制度は申請主義です。ルールを知らない人は、本来受け取れる給付を黙って取りこぼし続けます。制度は数千種類、要件は「年収X以下 かつ 世帯構成Y、ただしZの場合を除く」のような多段の条件分岐で、既存の検索サービスは候補を見せるだけ — 「あなたが該当するか」の判定と根拠の提示まではしてくれません。

### アプローチ: Gemini（理解）× Prolog（判定）のハイブリッド

お金と法律の領域で、LLM単体の回答はハルシネーションを排除できず致命的です。本作は役割を完全に分離しました。

- **Gemini Flash**: 「実は去年離婚してひとり親です」のような自由な発話から事実（ひとり親である・理由は離婚）を構造化抽出し、判定結果を自然な日本語で説明する
- **SWI-Prolog**: 抽出された事実に対して全制度を論理推論で一括判定。該当理由・条文根拠・証明木（推論ツリー）を生成し、判定を確定させるために「次に聞くべき質問」を未束縛の事実から機械的に導出する

判定結果は100% Prolog由来です。LLMがお金の判定に触れる経路が存在しないため、「ありもしない制度を案内する」「金額を捏造する」事故が構造的に起こりません。

### 品質の担保

- 収録220制度すべてに、公式ページ・条文から導出した期待値との照合テスト（golden 814ケース）を用意し、全件一致を CI で維持
- ユーザーに見せるのは golden 検証済みの制度のみ。制度数を盛るために信頼を売らない
- 判定は「見込み」の提示であり法的助言ではない旨を常に明示。最終確認は自治体窓口へ誘導

### 使い方

1. お住まいの区と生年月日・家族構成をチップのタップで入力（最短3タップで初回判定）
2. AIが「判定が最も進む質問」だけを選んで聞いてくる — 回答のたびに全制度を約0.5秒で一括再判定
3. チャットで自由に事情を話すと、Geminiが事実を汲み取って判定に反映
4. 「受給見込み」の制度カードから、月額・該当理由・条文リンク・Prolog推論ツリーを確認

### 技術構成

| 技術 | 用途 |
|---|---|
| Gemini Flash (Structured Output) | 発話からの事実抽出・応答生成（判定はしない） |
| SWI-Prolog | 全制度の該当判定・証明木生成・不足事実の特定 |
| FastAPI | ステートレスAPI（DBなし。入力された事実・発話は保存もログ出力もしない） |
| Cloud Run | swipl 同梱の単一コンテナでサーバーレス実行（東京リージョン） |
| Secret Manager / Cloud Build / Artifact Registry | APIキー管理・イメージビルド |

プライバシー: 家族構成・収入などの入力はリクエスト処理中のみメモリに存在し、どこにも保存・記録されません。

### スケールする設計

ルールは国レイヤ（全国共通）と自治体レイヤの2層構造。国制度は一度形式化すれば全国で有効、自治体追加は差分のみ — 制度・自治体を増やす限界費用が構造的に低いのがこのアーキテクチャの中心主張です。
